Open source · Rust · Self-hosted logging

Логи под вашим контролем.

Lognara собирает события приложений — HTTP, файлы и stdout/stderr, — доставляет их через дисковые очереди, которые переживают перезапуски, и показывает в веб-консоли: поиск, trace, паттерны, графики метрик и алерты. Всё работает на вашей инфраструктуре.

Возможности

Доставка, которой можно доверять, и поиск без отдельной базы.

01

Надёжная доставка

Agent и Relay отвечают 202 только после записи на диск. Очереди переживают обрывы связи и перезапуски и повторяют пачки, пока Core не подтвердит приём.

02

Полнотекстовый поиск

Tantivy индексирует текст сообщения. Фильтры по окружению, серверу, сервису, уровню и trace ID, пагинация курсором.

03

Хранение для логов

WAL с fsync до подтверждения, сегменты Parquet с ZSTD и суточное слияние сегментов. Retention 7 дней по умолчанию, при необходимости — предел по размеру.

04

Веб-консоль Dock

За nginx: вход по паролю или passkey, live-лента по SSE, история с графиком событий, Trace, паттерны, проблемы ошибок и аналитика.

05

Источники логов

HTTP-приём текста, JSON и байтов, файлы с ротацией и checkpoint, stdout/stderr через lognara-agent run, синк Serilog для .NET. Готовые примеры для Nginx, PostgreSQL, Seq и MinIO.

06

Гистограммы и группировки

Гистограммы по временным корзинам, group-by по одному-двум измерениям и сводка окна с p95 duration_ms. Вычисляет DataFusion.

07

Логи по trace ID

Все события одного trace в порядке времени. Это связанные логи, а не APM-waterfall: спаны не строятся.

08

Паттерны и проблемы ошибок

Core сворачивает повторяющиеся сообщения в паттерны и группирует ошибки по fingerprint. В Dock — скрытие паттернов, статусы проблем и возвраты.

09

Метрики из логов

Приложения пишут ServiceMetrics в логи, regex-правила задаются в Dock. Точки хранятся в Parquet с почасовыми и 12-часовыми агрегатами и не удаляются retention'ом логов.

10новое

Алерты метрик в Telegram

Dock раз в минуту оценивает правила по точным агрегатам Core и доставляет переходы состояния в Telegram через durable-очередь.

11новое

MCP для ИИ-ассистентов

Read-only удалённый MCP в Dock: девять инструментов для логов, trace, метрик и версий. Доступ по персональному токену или OAuth, по умолчанию выключен.

12новое

Мониторинг цепочки

Агенты и relay шлют heartbeat, Dock рисует дерево инфраструктуры со статусами узлов, местом на диске, WAL и retention.

Dock

Компоненты

Небольшие сервисы, у каждого одна задача.

Каждый сервис — отдельный Rust-crate с параметрами LOGNARA_*, которые проверяются при старте.

localhost · :7400

Agent

HTTP-приём текста, JSON и байтов, чтение файлов и захват stdout/stderr. Добавляет service, server и backend, пакует записи в MessagePack и zstd и отправляет их в Relay.

на хосте · :7401

Relay

Проверяет токен агента, распознаёт уровень, сообщение, action и trace ID — в том числе уровень nginx error_log. Группирует события по источнику и держит FIFO-очередь до подтверждения Core.

центр · :7402

Core

WAL с fsync, сегменты Parquet с ZSTD, индекс Tantivy, каталог SQLite. Поиск, trace, статистика, паттерны, проблемы ошибок, серии метрик, реестр relay и агентов и /metrics Prometheus.

за nginx · :7403

Dock

Веб-интерфейс: вход по htpasswd или passkey, логи, аналитика, метрики, алерты и управление подключениями relay и агентов. Токены core не попадают в браузер.

NuGet · Serilog

Клиент .NET

Пакет Serilog.Sinks.Lognara для .NET 8+ формирует канонические JSON-пачки и отправляет их агенту с буфером в памяти или на диске.

библиотека · без порта

Spool

Общая дисковая очередь Agent и Relay. Атомарные группы файлов: запись во временный каталог, fsync, rename. Порядок FIFO сохраняется, повреждённые данные не пропускаются молча.

Структура события

Ваш JSON становится структурированным событием.

Agent не меняет смысл записи. Relay извлекает известные поля, а остальные сохраняет целиком в attributes.

Поиск и статистика

HTTP API для поиска и аналитики.

Повседневные задачи закрывает веб-консоль Dock. Для собственных инструментов остаётся HTTP API core, а ИИ-ассистенты подключаются через read-only MCP в Dock.

POST/v1/logs/search

Фильтры по полям, полнотекстовый поиск по message, курсорная пагинация.

POST/v1/logs/sources

Различающиеся сервисы, серверы и окружения по удерживаемым сегментам.

GET/v1/traces/{trace_id}

Все события одного trace в порядке времени.

POST/v1/stats/histogram · group-by · summary

Корзины по времени, группировка по одному-двум полям и сводка окна: total, уровни, топ-5 ERROR-сервисов и p95 duration_ms.

POST/v1/patterns/search · /v1/issues/search

Паттерны повторяющихся сообщений и проблемы error/fatal по fingerprint.

GET/v1/series · POST/v1/series/query

Серии метрик из ServiceMetrics и regex-правил; длинные диапазоны из суточных агрегатов.

GET/v1/status · /metrics

Версия, готовность, состояние WAL и хранилища; метрики Core в формате Prometheus. Доступ по токену.

Пример · POST /v1/logs/search
Authorization: Bearer <QUERY_TOKEN>
{
  "from": "2026-11-04T10:00:00Z",
  "to": "2026-11-04T11:00:00Z",
  "filters": {
    "service": ["files", "api"],
    "level": ["error", "warn"]
  },
  "text": { "query": "connection refused", "mode": "phrase" },
  "limit": 100
}

Полнотекстово индексируется message. Поля attributes в фильтрах пока не участвуют.

Быстрый старт

Запуск за три шага.

Образы core, relay и dock публикуются в docker.barkfluff.com после CI; агент поставляется статическими бинарниками из GitHub Releases. Без Docker сервисы собираются из исходников, нужен Rust 1.94+.

1

Запустите Core и Dock

# docker-compose.yml, центральный сервер (фрагмент)
# master обновляется вместе с веткой; для фиксации укажите числовой тег образа из registry
services:
  lognara-core:
    image: docker.barkfluff.com/lognara-core:master
    environment:
      LOGNARA_LISTEN_ADDR: 0.0.0.0:7402
      LOGNARA_ADMIN_TOKEN: admin-secret
      LOGNARA_QUERY_TOKEN: query-secret
    volumes: [lognara-core-data:/var/lib/lognara-core]
  lognara-dock:
    image: docker.barkfluff.com/lognara-dock:master
    environment:
      LOGNARA_DOCK_LISTEN_ADDR: 0.0.0.0:7403
      LOGNARA_DOCK_PUBLIC_URL: https://dock.example.com
      LOGNARA_DOCK_CORE_URL: http://lognara-core:7402
      LOGNARA_DOCK_CORE_TOKEN: query-secret
      LOGNARA_DOCK_CORE_ADMIN_TOKEN: admin-secret
    volumes:
      - ./auth:/etc/lognara-dock/auth
      - ./dock-data:/var/lib/lognara-dock
volumes: {lognara-core-data: {}}
2

Добавьте машину приложений

# relay и агента создайте в Dock на странице «Подключения»:
# токен relay → LOGNARA_RELAY_CORE_TOKEN, токен агента → LOGNARA_AGENT_TOKEN

# docker-compose.yml на машине приложений
services:
  lognara-relay:
    image: docker.barkfluff.com/lognara-relay:master
    environment:
      LOGNARA_LISTEN_ADDR: 0.0.0.0:7401
      LOGNARA_CORE_URL: https://core.example.com/v1/batches
      LOGNARA_CORE_TOKEN: ${LOGNARA_RELAY_CORE_TOKEN}
    volumes: [lognara-spool:/var/lib/lognara-relay/spool]
volumes: {lognara-spool: {}}

# агент — бинарник из GitHub Releases — добавьте в образ приложения:
# LOGNARA_RELAY_URL=http://lognara-relay:7401/v1/batches
# LOGNARA_RELAY_TOKEN=${LOGNARA_AGENT_TOKEN}
3

Отправьте лог и найдите его

# отправить в Agent
curl -X POST http://127.0.0.1:7400/v1/logs \
  -H 'Content-Type: application/json' \
  -d '{"level":"error","message":"connection refused","action":"db.connect"}'

# найти: веб-консоль Dock или API core
curl -X POST http://127.0.0.1:7402/v1/logs/search \
  -H 'Authorization: Bearer query-secret' \
  -H 'Content-Type: application/json' \
  -d '{"from":"2020-01-01T00:00:00Z","to":"2100-01-01T00:00:00Z","filters":{"level":["error"]},"text":{"query":"connection refused","mode":"phrase"}}'

Токены в примере демонстрационные. Dock работает за TLS-прокси, например nginx, и требует файл htpasswd. Готовый Compose core + dock — Example/ в репозитории; сборка из исходников — cargo build --release в каждом crate.

FAQ

Вопросы, которые задают чаще всего.

Lognara — это облачный сервис?

Нет. Это набор сервисов, которые вы запускаете сами. Личного кабинета, SaaS и управляемого хостинга в проекте нет.

Гарантирует ли Lognara отсутствие потерь?

Нет. Гарантия относится к запросам, подтверждённым на исправном диске. Доставка работает по схеме at-least-once: повторы возможны. Неподтверждённый запрос приложение должно повторить само.

Что будет, если Core недоступен?

Relay сохраняет подтверждённые пачки на диске и повторит доставку после восстановления связи. Если очередь заполнится, новые запросы получат 503, и клиент должен отправить их снова.

Есть ли веб-интерфейс?

Да — Lognara Dock. Вход по паролю или passkey, live-лента и история логов, Trace, паттерны сообщений, проблемы ошибок, аналитика, дерево инфраструктуры, графики метрик и алерты в Telegram. Dock работает за nginx и не раскрывает токены core браузеру.

Можно ли подключить ИИ-ассистента?

Да. Dock отдаёт read-only удалённый MCP на /mcp с девятью инструментами: приложения, серверы и окружения, поиск логов, trace, сводки, метрики и версии. По умолчанию он выключен (включается LOGNARA_DOCK_MCP_ENABLED=true) и принимает персональный токен или OAuth; cookie браузера доступа к MCP не даёт.

Есть ли алерты?

Да, по метрикам. Dock раз в минуту оценивает правила по точным агрегатам Core и отправляет переходы состояния в Telegram.

Нужна ли внешняя база данных?

Нет. Используются локальные Parquet-сегменты, индекс Tantivy и SQLite-каталог. Нужен надёжный локальный диск.

Сколько хранятся логи?

По умолчанию семь суток по времени поступления; срок задаётся LOGNARA_RETENTION_SECONDS, предел размера — LOGNARA_RETENTION_MAX_BYTES. Закрытые сегменты сливаются по суткам. Точки метрик не удаляются, пока для них не задан отдельный срок.

Какие источники логов поддерживаются?

HTTP-приём текста, JSON и байтов; файлы с ротацией и checkpoint; stdout/stderr программы, запущенной через lognara-agent run. Для .NET 8+ есть синк Serilog.Sinks.Lognara. Docker API, journald и syslog не поддерживаются.

Можно ли строить метрики из логов?

Да. Приложения отправляют объект ServiceMetrics, либо вы задаёте в Dock regex-правило поверх обычных логов. Правила применяются к новым событиям без пересчёта истории. Точки пишутся в Parquet, длинные диапазоны читаются из суточных агрегатов, графики рисуются в Dock.

Можно ли искать по полям attributes?

Нет. Attributes сохраняются и возвращаются в событиях, но в текущей версии не индексируются.

Есть ли готовые Docker-образы?

Да: lognara-core, lognara-relay и lognara-dock публикуются в docker.barkfluff.com после прохождения CI. Отдельного образа агента нет: он поставляется статическими Linux-бинарниками (amd64 и arm64) из GitHub Releases и копируется в контейнер приложения.

Есть ли кластер и репликация?

Нет. Core работает одним процессом на каталог данных на локальном SSD: без кластера и репликации, TLS не встроен — HTTPS обеспечивает внешний прокси.

Какая лицензия?

MIT. Исходники открыты, их можно изучить, менять и использовать.
